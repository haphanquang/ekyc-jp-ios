# JPKI 全体像

eKYC アーキテクチャを検討する前に読む、公的個人認証サービス（JPKI）のリファレンス。用語・登場人物・認証フロー・手数料と、設計判断のためのチェックリストをまとめる。個別の実装手順は各スキル（`signature-verification`、`jlis-yukousei-kakunin`、`platform-jigyousha` など）を参照。

## このスキルを使う場面

- マイナンバーカードを使う eKYC / 本人確認機能を新規に設計し始めるとき
- 「署名用」と「利用者証明用」のどちらを使うか判断するとき
- プラットフォーム事業者（PF事業者）に委託するか、自らなるかを検討するとき
- J-LIS・署名検証者・手数料など、関係者と費用構造を把握したいとき

## JPKIとは

公的個人認証サービス（JPKI）は、マイナンバーカードのICチップに搭載された電子証明書を使って、オンラインで利用者本人の認証や電子文書の非改ざんを公的に確認する仕組み。マイナンバー（個人番号）自体は使わない。

- 根拠法は「公的個人認証法」。国と地方公共団体が共同管理する**地方公共団体情報システム機構（J-LIS）**が運営する。
- 電子証明書は市区町村の対面による厳格な本人確認を経て発行される。発行者である J-LIS が**トラストアンカー（信頼の基点）**となり、その有効性を証明する。
- 行政機関だけでなく民間事業者も導入できる（利用民間事業者は1,307社／2026年8月17日時点）。

電子証明書は2種類ある。

| 電子証明書 | 用途 | 基本4情報（氏名・住所・生年月日・性別） | 主な失効条件 |
|---|---|---|---|
| 署名用電子証明書 | 申込・契約など電子文書の作成・送信。「本人が作成し本人が送信した真正な文書」であることを確認できる | **保持する** | 有効期間満了、基本4情報の変更（引越し・婚姻等）、本人の死亡・国外転出等 |
| 利用者証明用電子証明書 | サイトへのログイン等。「利用者本人であること」のみを証明。発行番号でログイン者を特定 | 保持しない | 有効期間満了、本人の死亡・国外転出等（基本4情報の変更では失効しない） |

署名用電子証明書による電子署名は、電子署名法第3条（真正な成立の推定）の対象となり得る。

## 登場人物と2つの導入方式

| 用語 | 意味 |
|---|---|
| 署名検証者 / 利用者証明検証者 | 利用者から電子証明書を受け取り検証する民間事業者。署名用を検証するのが署名検証者、利用者証明用を検証するのが利用者証明検証者 |
| J-LIS（地方公共団体情報システム機構） | 認証局。電子証明書の発行・失効管理を行い、有効性確認の照会に応答する。トラストアンカー |
| プラットフォーム事業者（PF事業者） | 主務大臣認定を受け、自ら J-LIS に電子証明書の有効性を確認する事業者。有効性確認機能を他事業者へ「プラットフォーム」として提供できる |
| サービスプロバイダ事業者（SP事業者） | 自社で署名検証設備を持たず、有効性確認を PF事業者に委託してサービス提供する事業者 |

導入方式は2つ。**アプリが ICチップから電子証明書を読み取ること自体はどちらの方式でも可能**で、違いは有効性確認の経路にある。

| 方式 | 有効性確認 | 主務大臣認定 | 署名検証設備 | 期間・コスト |
|---|---|---|---|---|
| PF事業者になる | 自ら J-LIS へ照会 | 必要 | 自社整備（クラウド可） | 技術仕様の入手〜認定取得に6か月〜1年程度 |
| SP事業者になる | PF事業者へ委託 | 設備整備は不要（但書あり↓） | 不要 | 安価・迅速。PF事業者が定める利用料（事業者ごとに異なる） |

> **但書**: 犯収法の**取引時確認をカ方式（JPKI。2027年4月以降は新ヌ）で行う場合**、犯収法施行規則第6条第1項第1号カ の但書により、**特定事業者自身が「署名検証者」**（公的個人認証法第17条第1項第6号の主務大臣認定＋機構への届出）である必要がある。PF事業者は認定・届出・設備整備を代行できるが名義は特定事業者に帰属する。詳細は `honnin-kakunin-houhou`・`platform-jigyousha`・`references/hourei-eKYC.md`。ヘ方式（IC読取＋容貌）だけなら関係しない。

## 認証の流れ

民間事業者の場合、下記の「J-LIS へ有効性を照会・回答」の部分は PF事業者を経由する（[アーキテクチャ検討チェックリスト](#アーキテクチャ検討チェックリスト)参照）。

### 署名用電子証明書（例: e-Tax での確定申告、口座開設申込）

1. 利用者が、マイナンバーカードに格納された署名用の秘密鍵で電子文書を暗号化する（電子署名を生成）。
2. 文書本体とあわせて、暗号化した文書・公開鍵・署名用電子証明書を検証者へ送付する。
3. 検証者が、送付された公開鍵で暗号化文書を復号する。
4. 復号結果を文書本体と突合し、改ざんの有無を検知する。
5. 検証者が、電子証明書の有効性を J-LIS（認証局）へ照会する。
6. J-LIS が有効性を回答する。
7. 有効であれば認証成功（申請等が成立）。

### 利用者証明用電子証明書（例: マイナポータルへのログイン）

1. 検証者が乱数（チャレンジ）を生成し、利用者へ送付する。
2. 利用者が、マイナンバーカードに格納された利用者証明用の秘密鍵で乱数を暗号化する。
3. 乱数本体とあわせて、暗号文・公開鍵・利用者証明用電子証明書を検証者へ送付する。
4. 検証者が、送付された公開鍵で暗号文を復号する。
5. 復号結果を乱数本体と突合し、改ざん・すり替えの有無を検知する。
6. 検証者が、電子証明書の有効性を J-LIS へ照会し、回答を受ける。
7. 有効であれば認証成功。検証者は電子証明書の発行番号でログイン者を特定する。

## 手数料

J-LIS に対する電子証明書検証手数料は、有効性確認の件数に応じた従量課金制。

| 電子証明書 | 手数料 |
|---|---|
| 署名用電子証明書 | 20円 / 1件 |
| 利用者証明用電子証明書 | 2円 / 1件 |

- **2023年1月より当面無料**（CRL提供方式は恒久無料化、OCSPレスポンダ方式は当面3年間無料化）。
- 主務大臣認定の取得・維持自体に費用は発生しない。
- SP事業者の場合は、これとは別に PF事業者が定めるサービス利用料が発生する（事業者ごとに異なる）。

## アーキテクチャ検討チェックリスト

- [ ] eKYC の法的根拠を特定する（犯収法 / 携帯法 / 番号法 / 古物営業法 等）。方法の名称・時期は断定せず、詳細は `honnin-kakunin-houhou` / `references/method-map.md` を参照する。
- [ ] 署名用・利用者証明用のどちらを使うか決める（身元確認で基本4情報が必要なら署名用、当人認証・再ログインなら利用者証明用）。
- [ ] アプリで ICチップを読み取り、電子署名の生成まで端末内で行う設計にする（秘密鍵・暗証番号を端末外に出さない）。
- [ ] **電子証明書の有効性確認は必ず PF事業者経由で行う。アプリや未認定の自社サーバーから J-LIS へ直接照会しない。**
- [ ] PF事業者になるか、SP事業者として PF事業者に委託するかを選ぶ。
  - [ ] PF事業者になる場合: 主務大臣認定が必要。技術仕様の入手〜認定取得に6か月〜1年程度。
  - [ ] SP事業者になる場合: PF事業者を選定し、オペレーター契約を締結する。対応する読取方式・SDK/API・利用料・NDA 条件を比較する（`platform-jigyousha` 参照）。
  - [ ] **犯収法の取引時確認をカ方式（JPKI／新ヌ）で行うか**を確定する。行う場合、自社が「署名検証者」になる必要の有無・PF事業者の代行範囲・所要期間を法務・PF事業者に確認する（`honnin-kakunin-houhou` の但書）。
- [ ] スケジュールを見積もる。SP事業者の場合でも、PF事業者経由での AID開示申請・利用申込・J-LIS 側の手続きに時間を要する（目安は `platform-jigyousha` を参照。本スキルでは断定しない）。
- [ ] 「暗号的に正しい電子証明書」と「現在も有効な電子証明書」を分けて設計する。署名検証は `signature-verification`、有効性確認は `jlis-yukousei-kakunin` を参照。
