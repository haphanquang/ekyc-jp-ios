# 基本4情報と最新の利用者情報（4情報）提供サービスの同意

公的個人認証サービスの付加サービスである「最新の利用者情報（基本4情報）提供サービス」を自社に組み込む際の、基本4情報の定義・サービスの仕組み・総務省／デジタル庁が求める同意画面の要件・同意の有効期間と撤回をまとめたリファレンス。

- このサービスは**公的個人認証法（電子署名等に係る地方公共団体情報システム機構の認証業務に関する法律）に基づく**付加サービスであり、非対面の身元確認方法とは制度上のトラックが異なる。身元確認方法の選定・法的根拠・施行時期は本スキルでは扱わない。`honnin-kakunin-houhou` を参照。
- 取得した同意情報のサーバー側での保存・機構への送信・ライフサイクル管理は `doui-jouhou-kanri` を参照。
- 電子証明書の検証・有効性確認の全体像・登場人物は `jpki-overview` を参照。

## このスキルを使う場面

- 顧客の住所・氏名等の変更を郵送によらずオンラインで最新化する機能（最新の利用者情報（4情報）提供サービス）を設計するとき
- 「最新の基本4情報を機構から受け取ることについての本人同意」を取得する同意画面・導線を実装するとき
- 同意画面に何を表示し、「同意事項の詳細・補足説明」に何を書く必要があるかを確認するとき
- 同意の有効期間・撤回（取消し）・照会の実務フローを設計するとき
- 既存顧客からの同意取得にマイナポータルの「本人同意の取得支援サービス」を使うか検討するとき

## 基本4情報の中身

基本4情報 = **氏名・住所・生年月日・性別**。署名用電子証明書に記録されており、市区町村の対面による本人確認を経て記録される。最新の利用者情報（4情報）提供サービスにおける**同意の対象項目もこの4項目**（住所・氏名・生年月日・性別）。

各項目の範囲（PDF 09 の同意画面例 ※1・※2 に基づく）:

| 項目 | 範囲・注意点 |
|---|---|
| 氏名 | 旧氏を併記している場合は**旧氏も含まれる**。**令和8年5月26日（2026-05-26）以降は、氏名および旧氏の振り仮名も含まれる**（PDF 09 ※1 の文言：「令和8年5月26日以降は、氏名および旧氏の振り仮名も含まれます。」）。 |
| 住所 | 国外転出された場合は「**国外転出した旨**」および「**転出予定年月日**」も含まれる（PDF 09 ※2）。 |
| 生年月日 | — |
| 性別 | — |

- 機構から**プラットフォーム事業者（PF事業者）**へは、最新の基本4情報とあわせて**署名用電子証明書の発行の番号**が提供される。署名用電子証明書が失効した後、新たな署名用電子証明書が発行されていない間は提供が行われない。
- 発行番号の扱いには資料間で差異がある。PDF 05 §5(3) は「発行番号はサービスプロバイダ事業者へ提供する内容には含まれず、同意の対象とはならない」とする一方、PDF 09 の同意画面例・詳細説明1は機構→PF事業者への提供項目として発行番号を挙げる（サービスごとに記載を変更）。→ `## 未確認事項`

## 最新の利用者情報（4情報）提供サービスの仕組み

- **2023年5月16日開始。** 署名用電子証明書を利用する署名検証者向けの、公的個人認証サービスの付加サービス。
- 事前に本人同意を得ている前提で、引越し・改姓等により**署名用電子証明書が再発行された利用者**の最新の基本4情報を、機構（J-LIS）からいつでもオンラインで取得できる。郵送（往復ハガキでの住所確認）が不要になる。
- **提供経路：** PF事業者が機構から**直接**最新の基本4情報を受け取り、SP事業者（サービスプロバイダ事業者）は**PF事業者を経由して間接的に**受け取る。PF事業者は4情報を保管・管理せず、SP事業者へ提供後に廃棄する。保管・管理は機構と署名検証者（署名検証を PF事業者に委託する SP事業者を含む）が行う。
- **アプリや自社サーバーから J-LIS へ直接照会・送信しない。必ず PF事業者を経由する**（`jpki-overview` 参照）。

処理の流れ（PDF 05 図5-2）:

1. 利用者が市区町村窓口でカードの更新手続を行う → 更新前の署名用電子証明書は失効し、変更後の基本4情報が記録された署名用電子証明書が再発行される。
2. PF事業者が、SP事業者の求めに応じて、事前に取得していた更新前の署名用電子証明書の失効情報を機構から取得する。
3. PF事業者が、SP事業者と取り決めた任意の期間ごとに、署名用電子証明書の有効性を情報提供する。
4. SP事業者が失効を確認したら、PF事業者に最新の基本4情報の提供を求める。
5. PF事業者が機構に最新の基本4情報の提供を求める。
6. 機構が、同意が有効期限内か・取消しされていないか・同意対象項目が何かを確認する。
7. 機構が、同意している対象項目について PF事業者へ最新の基本4情報を提供する。
8. PF事業者が SP事業者へ提供する。

補足:

- 失効情報（CRL）は J-LIS から**1日1回程度（1日単位）更新**されローカルでオフライン照合できる。OCSPレスポンダ方式は15分単位。正確な更新時刻は要確認（`## 未確認事項`）。
- 手数料：PF事業者が機構から最新の基本4情報を取得する際 **1件あたり20円**。最新情報がない場合は手数料は発生しない。CRL方式の有効性確認手数料は2023年1月より無料（恒久）。
- **利用の前提：** まず公的個人認証サービス利用のための手続きが必要。SP事業者は委託先の PF事業者からシステム対応に必要な情報の提供を受ける。PF事業者は J-LIS へ本サービスの利用申込を行い、守秘義務の誓約のうえ技術仕様等の開示を申請する（`platform-jigyousha` 参照）。
- 対応 PF事業者の一覧は `references/pdfs/10_platform-operators-4-info-list.pdf`（令和8年6月10日時点：野村総合研究所・TOPPAN・NEC・NTTデータ・クラウドシップ・サイバートラスト・Workthy・ポケットサイン・ICTまちづくり共通プラットフォーム推進機構・プリマジェスト・ダブルスタンダード）。

### マイナポータルを活用した「本人同意の取得支援サービス」

- **2024年10月29日開始。** マイナポータルAPIを活用し、特に**既存顧客からの同意取得**を円滑化する。新規顧客は申込時に取得できるが、既存顧客向けの受け皿。
- 流れ（PDF 11）：SP事業者がハガキ・メール等で QRコード／リンクを送付 → 顧客がマイナポータルにアクセスし、同意対象（新住所等の◯◯企業への提供）を確認 → **マイナンバーカードで電子署名**して同意 → 同意情報・電子証明書情報（基本4情報）・PPID 等が SP事業者・PF事業者・J-LIS へ連携される。
- メリット：既存顧客の同意取得が容易、同意取得のシステム開発コスト低減、住所変更手続の事務コスト低減。

## 同意画面の要件

総務省自治行政局住民制度課マイナンバー制度支援室／デジタル庁国民向けサービスグループが PDF 09 で示す留意事項。同意は「利用者にとってわかりやすいこと」「確実に取得されること」が求められる。

### 画面の構成（PDF 09 Ⅰ）

- [ ] **表題・要旨・同意ボタンからなる独立した同意画面を設け、その全体を表示する**（他の規約等に紛れ込ませない）。
- [ ] 同意ボタンは「**同意する**」「**同意しない**」を用意する（同意は任意であり、不同意でも不利益を与えない）。
- [ ] 要旨に、**機構からお客様の最新の住所等（氏名・住所・性別・生年月日〔＋サービスにより署名用電子証明書の発行の番号〕）の提供を受けること**への同意である旨を、サービスに合わせて記載する。
- [ ] 同意画面の直下に「**同意事項の詳細・補足説明**」といった文言を置き、**クリックで全文表示される等、容易に確認できるようにする**。
- [ ] 詳細・補足説明の注記として、氏名の範囲（旧氏／令和8年5月26日以降は振り仮名）・住所の範囲（国外転出した旨・転出予定年月日）を記載する（PDF 09 ※1・※2）。

### 「同意事項の詳細・補足説明」に記載する15項目（PDF 09 Ⅱ）

各項目の【必須】【任意】は PDF 09 の表記どおり。**項目を新設・削除しないこと。**

- [ ] **1【必須】機構から本社への最新の基本4情報提供** — 本社が PF事業者を経由して機構に最新の基本4情報の提供の求めを行った場合、機構は PF事業者に対し最新の基本4情報（お客様が同意した情報に限る）及び署名用電子証明書の発行の番号を提供する。署名用電子証明書が失効した後、新たな署名用電子証明書が発行されていない間は提供しない。
- [ ] **2【任意】PF事業者から本社への最新の基本4情報提供** — PF事業者から本社に対し、機構から提供を受けた最新の基本4情報を提供する。
- [ ] **3【必須】最新の基本4情報の利用目的** — 機構より取得した最新の基本4情報は、定めた利用目的の達成に必要な範囲内でのみ利用する。利用目的は各利用場面で具体的に定めウェブサイト等で公表し、変更する場合は本人へ通知するかウェブサイト等で公表する。
- [ ] **4【必須】開示請求手続き** — お客様の求めにより、最新の基本4情報を取得した日時・取得した情報等の開示請求に対応する。本人確認のうえ所定の書式に記入いただき、後日回答する。所定の手数料をいただく。
- [ ] **5【必須】同意情報の保存・管理** — 取得した同意情報を公的個人認証法・個人情報保護法その他の法令に基づき適切に保存・管理し、保存の必要がなくなった場合は速やかに削除する。この同意情報は PF事業者を経由し機構に送信し、PF事業者・機構においても管理する。
- [ ] **6【必須】同意の取得方法** — **紙での取得は認めず、電子的に取得する。** 本人の意思に基づくことを確実に示すため、マイナンバーカードに係る電子署名及び署名用電子証明書を用いる。本社と PF事業者に提出され、署名用電子証明書の有効性確認と併せて機構に提供される。**同意の取得単位はサービスごと。** 本社は提出された署名用電子証明書を保持しない。
- [ ] **7【任意】同意の一括取得** — サービスごとに署名用電子証明書を付与する負担を軽減するため、ホールディング傘下の企業群が提供するサービス等について、各サービスへの明示的な同意を前提に一括で同意を取得する（一括取得する場合のみ記載）。
- [ ] **8【必須】同意の有効期間等** — 取得した同意の有効期間は、原則、同意の日の翌日を起算日として**10年**。同意の日は、同意の事実が機構のシステムに反映された日とする。有効期間内に署名用電子証明書が何度失効しても、有効期間中の同意は引き続き有効。有効期間内でも、お客様は何時でも同意取消の申請が可能。
- [ ] **9【必須】任意性の確保・同意しなかった場合** — 同意するか否かはお客様の任意。同意しない場合でも、本社サービスの提供が受けられない等の不利益を被ることはない。
- [ ] **10【必須】同意取消の申請による最新の基本4情報提供の停止** — 同意取消の申請があった場合、当該取消の事実が機構のシステムに反映された時点で有効期間が終了したものとみなし、機構から本社への提供を停止する。**同意取消はサービスごとに行え、当該サービスについてのみ終了・停止する。**
- [ ] **11【任意】本社サービス提供停止等による提供の停止** — 本社サービスの停止、又はお客様からのサービス利用停止の申し出があった場合は、原則としてサービス停止日の翌日より、機構から本社への提供を停止する。
- [ ] **12【必須】同意の照会・取消しの窓口** — 同意の照会・取消しは本社マイページ又は第15項の「お問い合わせ先」へ連絡する。**照会は利用者証明用電子証明書等により本人確認**を行い、**取消しは同意取消しに係る電子文書の送信を伴うため署名用電子証明書を用いる**。
- [ ] **13【必須】利用者クライアントソフトによる照会・取消し** — 機構が提供するアプリ「利用者クライアントソフト（JPKI Mobile）」をダウンロードし、お客様ご自身で同意の照会・取消しを行うことも可能（ダウンロード先の機構URLを記載する）。
- [ ] **14【任意】利用者クライアントソフトを用いた同意取消後の再同意** — 利用者クライアントソフトでの取消し後、再度同意する場合、利用者クライアントソフトによる再同意は不可であり、本社マイページでの再同意又は「お問い合わせ先」へ連絡する。
- [ ] **15【必須】最新の基本4情報提供についてのお問い合わせ先** — 会社名・住所・TEL を記載する。

必須＝1・3・4・5・6・8・9・10・12・13・15（11項目）／任意＝2・7・11・14（4項目）。

## 同意の有効期間・撤回

### 有効期間

- 原則、同意の**翌日**を起算日として**10年**。PDF 05 §5(5) の例：受付日時 2023-05-18 10:00:00 → 有効期間開始 2023-05-19 00:00:00 → 有効期間終了 2033-05-18 23:59:59。
- 有効期間内に署名用電子証明書が何度失効しても、有効期間中の同意は引き続き有効。
- 10年の有効期間が経過する前後に、署名検証者から利用者へ**同意の更新を促す必要がある**。
- 起算の基準日には資料間で差異（PDF 09「同意の事実が機構のシステムに反映された日」／PDF 05「SP事業者が受付した翌日」）。→ `## 未確認事項`

### 撤回（取消し）・照会

- 有効期間内でも、利用者は**何時でも同意取消しの申請が可能**。取消しは**サービスごと**に行え、当該サービスのみ停止する。
- 機構が取消し申請を受信次第、**即時に**機構から SP事業者への最新の基本4情報提供を停止する。
- **取消しの方法**：本人の意思を確実に示すため、同意申請時と同様に**署名用電子証明書**を用いる（同意取消しに係る電子文書の送信を伴う）。
- **照会の方法**：利用者証明用電子証明書等により本人確認を行う。
- **受付主体**：原則として、実務上利用者と接点を持つ SP事業者（窓口・マイページ等）。ただし次の場合は機構提供アプリ「利用者クライアントソフト（Windows版・Android版・Mac版・iOS版。JPKI Mobile）」でも照会・取消しを受け付ける。
  - 署名検証者・SP事業者の営業時間外
  - 複数事業者のサービスを一括で取り消したい場合
  - 緊急で取り消したい場合 等
- 利用者クライアントソフトで取消しをした後の**再同意は、利用者クライアントソフトでは不可**。SP事業者のマイページ等で行う。

## 未確認事項

- **J-LIS の CRL（失効情報）の具体的な更新時刻。** 読んだ一次資料は CRL を「1日1回程度（1日単位）更新」、OCSPレスポンダ方式を「15分単位」とのみ記載。特定の時刻（例：朝7時）は一次資料で未確認。
- **SP事業者向けの同意画面・SP事業者が受領する情報に「電子証明書発行番号（シリアル番号）」が含まれるか。** PDF 09 の同意画面例・詳細説明1は機構→PF事業者への提供項目として「署名用電子証明書の発行の番号」を挙げるが、PDF 05 §5(3) は発行番号を SP事業者へ提供せず同意対象外とする。サービス設計時に最新の PF事業者仕様で要確認。
- **10年の有効期間の起算基準日。** PDF 09 は「同意の事実が機構のシステムに反映された日」の翌日、PDF 05 は「SP事業者が利用者から同意を受付した日」の翌日とし、文言が一致しない。実務上の基準日は PF事業者仕様・機構仕様で要確認。
- **令和8年5月26日（2026-05-26）以降の氏名・旧氏の振り仮名提供**が、住民基本台帳法の氏名の振り仮名制度の施行に伴うものである点の一次資料での確認。本スキルは PDF 09 ※1 の文言のみを根拠とし、制度の背景は断定しない。
