# 同意情報のサーバー側管理（最新の利用者情報（4情報）提供サービス）

「最新の利用者情報（基本4情報）提供サービス」で利用者から取得した本人同意を、サーバー側でどう保存し、どのライフサイクルで管理し、機構へどう送信するかの手順・チェックリスト。

- 同意画面の要件・「同意事項の詳細・補足説明」15項目の**文言そのもの**は `kihon-4-jouhou-doui`。本スキルは 15項目を**コンプライアンス確認の形**（「〜が実装されているか」）でのみ扱い、全文を再掲しない。
- 身元確認方法の選定・犯収法／携帯法の号記号・施行時期は `honnin-kakunin-houhou` / `references/method-map.md`。**犯収法上の確認記録の保存義務（契約終了日等から 7 年）は `honnin-kakunin-houhou` の「確認記録の作成・保存」**。いずれも本スキルの「同意の有効期間（10 年）」とは根拠条文・起算日・対象の異なる別制度であり、本スキルでは断定しない。
- 署名検証の暗号処理は `signature-verification`、有効性確認は `jlis-yukousei-kakunin`、セッションの状態遷移・監査ログは `ekyc-session-orchestration`。
- 「本社」＝サービスプロバイダ事業者（SP事業者）／署名検証者、「PF事業者」＝プラットフォーム事業者、「機構」＝地方公共団体情報システム機構（J-LIS）。

## このスキルを使う場面

- 最新4情報提供サービスの同意を受け付けたあと、サーバーの同意情報データベースに何を保存するか（何を保存してはいけないか）を決めるとき
- 同意の有効期間（10年）・更新案内・撤回（取消し）の状態管理を設計するとき
- 利用者からの開示請求（取得日時・取得した情報の開示）に応える窓口・手続きを設計するとき
- 取得した同意情報を PF事業者経由で機構へ送信するフローを設計するとき
- 署名時に受け取った署名用電子証明書・電子署名をいつまで持つか判断するとき

## 保存すべき項目 / 保存してはいけない項目

同意情報は自社でデータベース等を構築して保存・管理する（PDF 09 詳細説明5、PDF 05 §5(3)①）。各事業者と機構がそれぞれ同意情報を保存・管理する。

### 保存すべき項目

- [ ] **同意日時**：同意の事実が機構のシステムに反映された日（＝「同意の日」。PDF 09 詳細説明8）。受付時刻もあわせて記録する。
- [ ] **同意した対象項目**：住所・氏名・生年月日・性別のうち利用者が同意した項目（機構は同意した項目に限り提供する。PDF 05 §5(3)）。
- [ ] **同意の単位（サービス）**：同意はSP事業者のサービスごと。一括取得した場合は対象サービスの一覧（PDF 09 詳細説明6・7）。
- [ ] **表示した同意文言のバージョン／本文**：利用者に表示した同意画面・「同意事項の詳細・補足説明」の版（あとで開示・説明できるようにする）。
- [ ] **同意ID・取得経路**：自社同意画面での取得か、マイナポータルの「本人同意の取得支援サービス」経由か（PDF 11）。機構・PF事業者との突合に使う識別子。
- [ ] **有効期間・状態**：起算日、満了予定日、現在の状態（有効／更新案内済み／取消し受付／取消し反映済み／満了）。
- [ ] **機構への送信結果**：PF事業者経由で送信した日時・受理結果・エラー（監査用。`ekyc-session-orchestration` の監査ログと整合させる）。

**要確認（保存項目に含めるか未確定）：署名用電子証明書の発行の番号（シリアル番号）。** 機構→PF事業者では連携キーとして提供されるが、PDF 05 §5(3) は発行番号を「サービスプロバイダ事業者へ提供する内容には含まれず、同意の対象とはならない」とする。SP事業者が受領・保存する範囲は最新の PF事業者仕様で確認し、確定するまで既定の保存項目にしない。→ `## 未確認事項`（`kihon-4-jouhou-doui` の未確認事項と同じ）

### 保存してはいけない項目

> **適用範囲**: この「非保持」ルールは、**最新4情報提供サービスの同意取得**で利用者が提出した署名用電子証明書・電子署名について定めるもの（PDF 09 詳細説明6）。**犯収法の取引時確認をカ方式（JPKI／新ヌ）で行った場合は別**で、犯収法施行規則第19条第1項第2号により確認記録へ「確認を行ったことを証するに足りる電磁的記録」（実務上は電子署名と署名用電子証明書）を添付し 7 年保存する必要がある（`references/hourei-eKYC.md` §1、`honnin-kakunin-houhou`「確認記録の作成・保存」、`signature-verification`「検証後に保持するもの／しないもの」）。**同意情報ストア（非保持・10年）と犯収法の証跡ストア（電子署名＋証明書・7年）を別に設計する。**

- [ ] **利用者が提出した署名用電子証明書そのもの**を（同意サービスの目的では）保持しない。PDF 09 詳細説明6：「本社は、お客様が提出された署名用電子証明書を保持することはありません」。突合・検証に必要な範囲（発行番号（保存可否は要確認・上記）、検証結果、同意した項目）を超えて証明書 DER を残さない。
- [ ] **同意登録後の生の電子署名**を（同意サービスの目的では）保持しない。署名は本人の意思を示すために用い、SP事業者・PF事業者を経由して機構へ提供したら、検証結果と監査に必要な証跡（署名検証の成否、タイムスタンプ、識別子）のみを残す。生値・秘密鍵・暗証番号は残さない（`signature-verification` / `ekyc-session-orchestration` の「保存しない」項目と一致させる）。
- [ ] **保存の必要がなくなった同意情報**は速やかに削除する（PDF 09 詳細説明5、公的個人認証法・個人情報保護法その他の法令に基づく）。
- [ ] 機構から取得した**最新の基本4情報**の扱いは本サービスの結果データであって同意情報ではない。サービス停止・認定取消し時の消去は PDF 05 §5(6)イ を参照。PF事業者は4情報を保管せず提供後に廃棄する（PDF 05 §5(1)）。

## 有効期間と撤回

### 有効期間（PDF 09 詳細説明8）

- 取得した同意の有効期間は、**原則、同意の日の翌日を起算日として10年**。
- **「同意の日」は、同意の事実が機構のシステムに反映された日**とする。
- 有効期間内に署名用電子証明書が**何度失効しても**、有効期間中の同意は引き続き有効（再発行・失効で同意はやり直しにならない）。
- 有効期間内でも、利用者は**何時でも**同意取消の申請ができる。
- 10年が経過する前後に、署名検証者から利用者へ**同意の更新を促す必要がある**（PDF 05 §5(3)⑤）。あわせて、少なくとも1年に1回、同意項目の再確認・変更有無のリマインドを行う（PDF 05 §5(6)ア④）。
- 起算基準日は資料間で差異：PDF 09 は「機構のシステムに反映された日」の翌日、PDF 05 §5(3)⑤ は「SP事業者が受付した日」の翌日（例：受付 2023-05-18 10:00:00 → 開始 2023-05-19 00:00:00 → 満了 2033-05-18 23:59:59）。→ `## 未確認事項`

### 撤回（取消し）

- 取消しは**サービスごと**に行え、当該サービスについてのみ提供を終了・停止する（PDF 09 詳細説明10）。
- 取消しの事実が**機構のシステムに反映された時点**で有効期間が終了したものとみなし、機構から本社への最新4情報提供を停止する（PDF 09 詳細説明10）。機構が取消し申請を受信次第、即時に停止できる（PDF 05 §5(4)）。
- **取消しの本人確認は署名用電子証明書**（同意取消しに係る電子文書の送信を伴うため）。**照会の本人確認は利用者証明用電子証明書等**（PDF 09 詳細説明12、PDF 05 §5(5)①②）。
- 受付主体は原則 SP事業者（本社マイページ・お問い合わせ先）。営業時間外・複数事業者の一括取消し・緊急時は、機構提供アプリ「利用者クライアントソフト（JPKI Mobile。Windows／Android／Mac／iOS版）」で利用者自身が照会・取消しできる（PDF 09 詳細説明13、PDF 05 §5(5)）。
- **機構は同意取消しを自動通知しない。** 利用者クライアントソフト経由の取消しは、PF事業者が SP事業者ごとに割り振られたIDを用いて機構から取消し情報を取得し、SP事業者は PF事業者経由で取消し状況を照会して把握する（PDF 05 §5(5)③）。定期的な取消し状況の取り込みを設計する。
- **利用者クライアントソフトで取消した後の再同意は、利用者クライアントソフトでは不可。** 本社マイページでの再同意、またはお問い合わせ先への連絡による（PDF 09 詳細説明14、PDF 05 §5(5)④）。この導線をヘルプ・同意事項に明記する。

## 開示請求対応

PDF 09 詳細説明4、PDF 05 §5(6)ア②。

- [ ] 利用者の求めにより、**最新の基本4情報を取得した日時**および**取得した情報**等を開示する手続きを用意する。
- [ ] 請求者が**本人であることを確認**する。実務上、照会は利用者証明用電子証明書等で本人確認する（PDF 09 詳細説明12）。
- [ ] **所定の書式**に記入いただいたうえで手続きを行い、後日回答する。
- [ ] **所定の手数料**を定める。
- [ ] 開示請求の窓口・手続きを、プライバシーポリシー・利用規約等で事前に案内し、同意取得前に明らかにしておく（PDF 05 §5(6)ア②）。

## 機構への送信フロー（プラットフォーム事業者経由）

- [ ] 同意は**電子的にのみ**取得する（**紙不可**）。マイナンバーカード（またはスマートフォン搭載）の**署名用電子証明書による電子署名**で取得する（PDF 09 詳細説明6、PDF 05 §5(3)②）。
- [ ] 取得した同意情報・電子署名は **SP事業者 → PF事業者 → 機構** の経路で電子的に送信する（PDF 09 詳細説明5、PDF 05 §5(3)①）。署名用電子証明書の有効性確認とあわせて機構に提供される（PDF 09 詳細説明6）。
- [ ] **自社サーバー・アプリから機構（J-LIS）へ直接照会・送信しない。必ず PF事業者を経由する**（`jpki-overview` / `jlis-yukousei-kakunin` 参照）。
- [ ] 送信後、**同意情報は SP事業者・PF事業者・機構がそれぞれ保存・管理する**（PDF 05 §5(3)①）。自社側の保存内容と機構側の状態（有効期限内か・取消しされていないか・同意対象項目）を突合できるようにする（機構は最新4情報の提供時にこれを確認する。PDF 05 §5(2)⑥⑦）。
- [ ] 送信・受理・エラーを監査ログに残す（`ekyc-session-orchestration`）。生の署名・証明書 DER は監査ログにも残さない。
- [ ] サービス停止・利用停止時は、PF事業者経由で機構へ事前にサービス停止日を連携し、機構からの提供を停止する（PDF 05 §5(6)イ①）。

## 15項目コンプライアンスチェックリスト

PDF 09「Ⅱ 同意事項の詳細・補足説明」の15項目が、同意画面と自社の運用に反映されているかを確認する。**各項目の文言・【必須】／【任意】の別は `kihon-4-jouhou-doui`「『同意事項の詳細・補足説明』に記載する15項目」を正とする。** ここでは実装確認の観点のみを挙げる。

- [ ] **1 機構→本社の提供【必須】**：PF事業者経由で機構に求め、同意した情報＋発行番号が提供される旨を記載しているか。証明書失効中は提供されない旨を含むか。
- [ ] **2 PF事業者→本社の提供【任意】**：該当する場合に記載しているか。
- [ ] **3 利用目的【必須】**：機構から取得した最新4情報の利用目的を具体的に定め、ウェブサイト等で公表しているか。変更時の通知・公表手順があるか。
- [ ] **4 開示請求手続き【必須】**：`## 開示請求対応` の手続き（本人確認・所定書式・手数料・後日回答）が用意され、同意事項に案内されているか。
- [ ] **5 同意情報の保存・管理【必須】**：`## 保存すべき項目 / 保存してはいけない項目` のとおり適切に保存し、不要時に速やかに削除するライフサイクルがあるか。PF事業者・機構でも管理される旨を記載しているか。
- [ ] **6 同意の取得方法【必須】**：紙取得を排除し**電子的取得のみ**か。**署名用電子証明書による電子署名**で取得し、**提出された署名用電子証明書を非保持**にしているか。取得単位が**サービスごと**か。
- [ ] **7 同意の一括取得【任意】**：一括取得する場合、対象サービスを具体的・網羅的に明示し、各サービスへの明示的同意を取得しているか。
- [ ] **8 同意の有効期間等【必須】**：起算日＝同意の翌日、同意日＝機構システム反映日、**10年**、証明書が失効しても同意は有効、何時でも取消し可、を `## 有効期間と撤回` のとおり管理しているか。更新案内フローがあるか。
- [ ] **9 任意性の確保【必須】**：同意しなくても不利益を被らない旨を記載し、運用が一致しているか。
- [ ] **10 取消しによる提供停止【必須】**：取消しの機構システム反映時点で有効期間終了とみなし、当該サービスのみ提供停止する処理があるか。
- [ ] **11 サービス停止等による提供停止【任意】**：該当する場合、サービス停止日翌日からの提供停止を機構へ連携しているか。
- [ ] **12 照会・取消しの窓口と本人確認【必須】**：本社マイページ／お問い合わせ先の導線があり、**照会＝利用者証明用**、**取消し＝署名用**で本人確認しているか。
- [ ] **13 利用者クライアントソフトによる照会・取消し【必須】**：JPKI Mobile で利用者自身が照会・取消しできる旨と機構のダウンロード先URLを記載しているか。取消し情報の取り込みフロー（PF事業者経由）があるか。
- [ ] **14 利用者クライアントソフト取消し後の再同意【任意】**：JPKI Mobile での再同意は不可、本社マイページ／お問い合わせ先で再同意する旨を記載しているか。
- [ ] **15 お問い合わせ先【必須】**：会社名・住所・TEL を記載しているか。
- [ ] **同意画面の構成**（独立した表題・要旨・「同意する」／「同意しない」・詳細説明リンク）が `kihon-4-jouhou-doui`「同意画面の要件」を満たすか。
- [ ] 既存顧客の同意取得にマイナポータル「本人同意の取得支援サービス」を利用するか検討したか（PDF 11、`kihon-4-jouhou-doui`）。
